# 实现结构与技术决策

版本：V0.2，2026-10-19。

面部更新：FaceMotion是可独立测试的闲置眨眼与语音包络时间轴；FaceRenderer（Android为FacialRenderer）按六种姿态的局部标注连续渲染眼球、眼睑和口型。嘴巴命中优先于坐姿/肚子点击，超过拖动阈值取消语音；姿态切换、窗口隐藏或销毁时停止播放。Windows使用waveOut设备位置，Android使用MediaPlayer位置作为语音时间来源，重复点击重播而不叠加声音。面部变形不改变角色的透明命中轮廓。

## 平台选择

原方案推荐 Flutter，共享 Dart 产品逻辑，并允许 Windows 原生透明窗口作为后备。本机没有 Flutter、Dart 或 .NET SDK，但具备 .NET Framework 4.8 编译器与运行时。为交付真实可运行的桌面程序，本轮选用 C#＋Win32 分层窗口；Android 使用原生 Java 与官方 SDK 构建，避免引入未经验证的第三方悬浮插件。

这是对推荐工具链的明确调整：当前共享的是素材与行为协议，**不是同一份 Dart 运行代码**。两端状态机分别实现、通过实际资源清单导出的相同夹具验证。后续若改用 Flutter，应保留素材协议、行为用例与原生宿主能力边界，再评估迁移。

## 时间轴与取消

宿主按单调时钟提供经过的时间，核心不启动独立计时器或网络任务。动作保存当前可见帧、最新目标、转场进度及方向。点击改变目标时可原地反转当前转场，避免叠加播放器。退出到 `idle` 的路径同时充当其他姿态的连接点；目标改变为第三种姿态时继续经过该连接点，避免先折返再重走同一路径。

原晃动保留 37 帧、4390ms 的逐帧时序，入口/出口各约220ms另计。源 GIF 的绘制帧率由素材自身决定；宿主约16ms调度，并不会为一张不变的图反复重绘。

## Windows

窗口使用 `WS_EX_LAYERED`、`WS_EX_NOACTIVATE` 与 `UpdateLayeredWindow`，保留角色区域输入，并利用 alpha 为零区域的原生命中行为。没有对整个窗口设置鼠标穿透。缩放时明确指定图像的像素矩形，避免 PNG 的 DPI 元数据改变图像尺寸。

拖动抓取点使用角色逻辑坐标；工作区按当前显示器确定，进入24DIP、离开48DIP，预览稳定约120ms，松手立即确认。右边采用镜像后的连接点。`WM_DPICHANGED` 读取窗口消息中的新 DPI 与建议位置，避免把其他屏幕上光标的 DPI 误当作窗口 DPI。[Microsoft 消息说明](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged)

## Android

应用内从实际 WindowInsets/可见窗口范围获取键盘状态，Android 8–10 使用可见范围变化的兼容检测。系统悬浮采用不获取输入焦点的窗口；跨应用几何服务可选开启，并只检查窗口类型和边界。系统悬浮矩形被裁到角色可见范围，但该矩形内部透明角落的触摸穿透没有被当作已解决。

`PetView` 在窗口不可见、视图隐藏或脱离时移除更新任务，恢复可见时重置时钟，避免隐藏时间一次性推进旧动作。屏幕关闭或锁屏会移除悬浮视图，权限撤销会停止服务。

## 智能扩展

两端提供对话、记忆、工具清单及角色意图接口。目前不发起模型请求、不收集记忆、不执行电脑操作。后续按明确需求实现，网络失败不应阻塞本地角色互动。
