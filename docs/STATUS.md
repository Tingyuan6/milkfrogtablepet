## V0.4.0 放屁互动和大笑内轮廓

正式角色名“奶蛙”。两端趴姿在屁股缝(78,250)处放出源视频绿色气体，点击热区中心(78,248)、半径34×28，排除嘴巴和腹部；拖动不触发。播放90帧/30fps/3000ms，原趴姿身体保留，眼睛向屏幕左边移动约6像素并脸红；首尾与原趴姿一致。再次点击重播，拖动或嘴巴语音中断效果。Android隐藏、锁屏移除和分离窗口时停止效果及音频。视频原片段9.2—12.2秒，源文件已裁剪至仅含该片段的特效区域，来源摘要在fart-provenance.json。

大笑修复针对源帧150—214的中性白背景，保护嘴腔中的牙齿和奶油肚皮；由修复后的源帧重新生成相关过渡。Windows继续使用已修复的连续互动调度。Android0.4.0/versionCode7，保留原证书和原始ZIP路径验证。验证记录见 verification/fart-assets.json、fart-native.json、laugh-assets.json 和v0.4.0-release.json。安卓真机效果仍待实际安装验收。

## V0.3.1 Windows 修补

恢复期间的新大笑请求不再被丢弃；后续点击可取消待播放请求。鼠标/Enter监听在独立消息线程运行，减少视频渲染阻塞造成监听失效的风险。每次语音重新打开设备和缓冲，大笑退出时释放播放器并刷新面部绘制；原安迪录音、嘴型材质和全部美术资源不变。桌面文件、文件夹、应用快捷方式及此电脑/回收站等虚拟项目均按有效图标识别；资源管理器也允许打开文件夹。标准打开动作目前仍为双击或选中后按Enter。

新增 LifecycleTests 在奶蛙自己的窗口中验证恢复期间重开、再次点击取消待播放、站立/左右/底部各阶段中断后说话、完整视频循环后的说话与重开，以及主绘制线程暂停时监听线程仍能处理消息。旧0.3.0源码在“恢复期间再次打开”回归中失败；旧版在受控宿主中未复现用户的无嘴型现象，因此音频生命周期修补仍需在用户原设备复测。真实桌面项目触发与用户电脑音频驱动行为不能由受控宿主测试替代。结果见 verification/v0.3.1-lifecycle.json。

验证通过：C#核心267、面部617431、大笑/项目激活16664（449个中断位置）、连续互动90项；18轮实际音频重播均观测到播放时间推进和多个嘴型。独立监听消息处理、安装/卸载、Shell可用以及原生窗口回归通过。详见 verification/v0.3.1-release.json。

本轮仅更新Windows，Android保留0.3.0（versionCode6），无需重装。

## V0.3 嘴型和文件大笑

两端六种稳定姿态的“安迪”口腔加入上、下牙齿、粉色舌头、舌沟和口腔阴影，仍由原两秒WAV的实际播放位置驱动。闭嘴原图、原角色轮廓和全部原有语音/目光/眨眼交互保留。

Windows新增资源管理器和桌面的文件激活互动：单击仅识别项目，符合系统双击时间与距离的第二击，或文件列表选中项目后按Enter，触发大笑。0.3.1起文件夹和桌面虚拟图标也可触发；空白、搜索/重命名输入框和其他应用不触发。识别在后台核对Shell项目及文件存在性，低级输入回调只投递事件并继续正常输入链；不读取文件内容，不记录路径或键盘历史。托盘提供“打开文件时大笑”开关和“停止大笑”。目前不覆盖第三方文件管理器、系统单击打开设置及右键菜单打开。

大笑使用用户提供的Naiwa.mp4：去掉白色背景，保留原动作和声音，固定尺度与足底基线，参考现有idle调整黄色及奶油腹部色调。去掉前1.7秒等待，从视频提取411个源帧；原片末尾由倒地直接剪切到站立，本版用原动作反向起身和光流桥接替代该剪切，得到449个播放帧、30fps、约14.97秒的连续循环，声音补齐至同一周期。加入320ms进入转场以及每100ms的280ms退出补帧。点击任意区域先立即停止声音，再返回原姿态和位置；倒地期间先以原片段反向起身再转场，避免横躺身体直接拉伸到直立，视觉恢复最长约1.5秒。边缘触发时暂时移入屏幕，结束后恢复。

Windows大笑素材单独存放于assets/windows，不进入Android APK。Android0.3.0/versionCode6仅同步嘴型，并保留0.2.2全部路径校验及原签名。源视频在assets/source/laugh.mp4，生成工具与固定依赖已提供；视频抠图边缘、转场和实际文件触发仍应在用户电脑上进行视觉/使用验收。新的检查报告见 verification/laugh-assets.json、verification/laugh-native.json。

验证：C#原核心267项、面部617431项（含六姿态牙齿/舌头与轮廓保留）、大笑/激活16659项（449个中断位置，最长恢复1456ms）通过；Java原核心164、面部111、定位218、新口腔材质31417及打包7项通过。素材7559项检查，449个播放帧、151条退出路径、1480张引用PNG通过透明背景、320画布、站立148×260及足底290基线检查。Windows受控宿主验证从右侧停靠触发、实际音频播放、点击停止声音、恢复布局坐标、全局监听安装/卸载以及普通桌面进程的Shell接口访问；这不等于已验证用户真实资源管理器的双击或Enter行为。安卓编译、全部415个共用素材原始ZIP路径/字节和v2/v3签名通过，仍待真机界面验收。

## V0.2.2 安卓素材路径修复

用户提供Xiaomi 24129PN74C、Android15/API35实际日志，确认根因是 `AssetManager.open("poses/idle.png")` 失败。旧APK原始条目包含Windows反斜杠，Android按正斜杠查询无法找到；电脑ZIP库自动转换路径，原验证漏检。新的SDK打包器规范化413个素材路径，保留图片及音频原字节和存储方式，再进行对齐、签名。没有改动角色、美术、互动逻辑或Windows代码。

新签名APK逐项通过415个素材的原始本地头/中央目录路径和字节一致性检查，WAV未压缩，v2/v3签名有效且证书与0.2.1一致。新增7项打包回归包括反斜杠复现、修复后访问、缺失素材、内容变化、重复路径和越界路径拒绝；旧0.2.1 APK被新检查正确拒绝。Java交互164、面部111、定位218项继续通过。Android版本0.2.2、versionCode5，可直接覆盖安装；Windows继续使用0.2.1。

已根据实际包内容确认并修复路径缺陷，**仍未连接原问题手机进行真机显示、悬浮和语音验收**。请安装0.2.2复测，不将编译或ZIP验证等同于真机验收。参见 [安卓排错步骤](ANDROID-TROUBLESHOOTING.md) 和 [打包报告](verification/android-packaging.json)。

## 尚需验收与已知限制

1. **Android 界面尚未做真机/模拟器验收。** 编译通过不等于键盘位置、原输入框焦点、厂商后台保活或触摸穿透已经验证。手机/平板、横竖屏、分屏、实体键盘与不同输入法需逐项记录。
2. 系统悬浮透明角落可能拦截下方触摸。已缩小窗口，未宣称所有透明像素系统穿透。跨应用键盘几何需要用户手动开启可选服务；部分输入法窗口信息可能不可靠。
3. 大幅换姿使用生成的中间姿态与光流，局部存在纹理拉伸、手臂衔接和比例/色调变化。视觉终验T17仍待精修及确认。
4. 已在150%主屏测试；100%/200%、负坐标副屏、显示器增删与不同任务栏布局尚需实际组合验收。
5. 截图与机器指标仅反映本次测试环境，不构成持续30fps或全平台性能保证。原GIF有自己的低帧率节奏；应另测Release环境下的输入延迟、转场帧率与长期内存。
6. 本地开发签名APK是测试安装包；应用商店发布、正式签名与分发流程未在本轮执行。
