# 安卓看不到奶蛙或启动闪退

请先覆盖安装最新V0.3.0，无需卸载；该版本包含0.2.2素材路径修复。打开应用后，应在页面中看到奶蛙；应用内显示不需要悬浮权限。

1. 点击“开启桌面奶蛙”，在系统页面中为奶蛙允许“显示在其他应用上层／悬浮窗”。
2. 返回奶蛙，应用会继续尝试开启。悬浮角色实际画出后，状态才显示“桌面奶蛙已开启”。
3. 想在应用页面里重新找到角色，点击“找回应用内奶蛙”。这会收起桌面悬浮，并把应用内角色放回可见区域。
4. 如果显示“奶蛙加载失败”或“桌面奶蛙未能开启”，点这行提示，再点“复制错误信息”，把文本反馈给开发者。无需连接电脑或使用调试命令。
5. 如果发生未处理的闪退，重新打开应用后也可以查看上次保存的错误。错误只保存在手机应用内；复制由用户主动触发，不会自动发送。

V0.2.1修正了初始化失败后仍访问角色对象的路径，不再用普通权限状态覆盖原始初始化错误；调整初始定位、显式像素绘制、悬浮窗口上下文及通知图标，并在窗口失败时保留应用内角色。仅凭“空指针异常”不能确定旧版本的完整调用栈；这次补丁仍需要在出现问题的设备复测。

## 已确认的0.2.1素材路径问题

Xiaomi 24129PN74C、Android15/API35的日志为 `Missing asset poses/idle.png`，底层异常为 `AssetManager.open` 的 `FileNotFoundException`。检查旧APK原始ZIP条目后，实际名称是 `assets/poses\\idle.png`，语音和补帧目录也存在反斜杠。Windows上的Python ZIP库会自动规范化这些名称，之前仅用它查询文件是否存在，漏掉了Android无法匹配原始路径的问题。

V0.2.2构建把413个子目录素材路径统一为正斜杠，再进行对齐、签名。新验证同时读取原始本地头及中央目录中的名称，逐字节对照全部415个源素材，检查WAV未压缩；任意缺失、重复、错误路径或内容变化都会阻止构建通过。新检查可准确拒绝旧0.2.1安装包。

已验证编译、素材完整性、签名及覆盖安装所需的签名一致性；尚无连接的手机，不能把这些检查视为已完成小米真机验收。升级后先确认应用内角色出现，再点击“开启桌面奶蛙”。如仍有错误，请复制新版日志。
