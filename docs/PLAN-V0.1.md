# 奶蛙桌宠开发计划 V0.1

日期：2026-10-18。目标平台：Windows 电脑、Android 手机和平板。

本文是可交给 Codex 执行的产品与技术方案。本次交付为规划及素材整理，原生悬浮窗口、Android 键盘联动和新过渡动画尚待开发、制作与实机验证。

## 1. 产品目标与本轮范围

奶蛙是一只使用现有黄色角色素材的桌面陪伴宠物，后续具备轻量智能体能力。开发顺序为：Windows 交互原型 → 连贯动画与停靠 → Android 适配 → 智能能力。

本轮先锁定用户已经提出的交互，暂不自行增加聊天入口、语音、联网搜索、电脑操作等产品流程。智能层保留接口，具体首批智能功能由下一轮需求确定。基础动作、拖拽和眼睛跟随全部在本地运行，独立于模型服务。

### 已确定的需求

| 编号 | 用户要求 | 本方案的具体行为 |
|---|---|---|
| R01 | 名称与形象 | 名称为“奶蛙”，使用现有已处理的黄色角色及统一肤色、比例 |
| R02 | 静止状态 | 使用本次附带的 `原始可爱蛙.png`，保留透明通道 |
| R03 | 眼睛跟随 | 鼠标靠近奶蛙时，瞳孔平滑跟随光标；离远后平滑回正 |
| R04 | 点击腹部 | 自由站立时点击腹部，进入 `晃动一.gif` 的互动 |
| R05 | 播放与中断 | 默认完整播放一遍后回到静止；播放期间再次点击，平滑返回静止 |
| R06 | 连贯过渡 | 静止与晃动、坐姿一与坐姿二之间制作真实桥接帧，保证衔接 |
| R07 | Android 键盘联动 | 软件键盘打开时，以“坐姿一”停靠在键盘上缘，点击后连贯切换为“坐姿二” |
| R08 | Windows 底部停靠 | 拖到桌面底部，切换为“底部一” |
| R09 | Windows 左右停靠 | 拖到最左侧，使用“左右一”；拖到最右侧，水平镜像同一素材 |
| R10 | 可扩展性 | 后续增加动作、皮肤、智能能力时，通过素材描述、状态规则和接口扩展 |

### 为了能够实现而采用的暂定规则

以下属于可调整默认值，不代表用户已额外要求：

1. Android 坐姿一切到坐姿二后保持；再次点击切回坐姿一。
2. 关闭软件键盘后恢复打开键盘前的停靠位置，回到该位置的基础姿态。
3. Windows 的“底部”默认指当前显示器可用工作区的底边，即任务栏上方。左右边界也使用该工作区；支持负坐标的副屏。
4. 落在左右下角时，左右停靠优先于底部停靠。
5. 侧边和底部状态本轮保持对应姿态；拖离边缘后回到自由站立，再进行腹部晃动互动。
6. 软件键盘出现时，键盘坐姿优先于正在播放的晃动。当前动作经短过渡退出，不直接换图。
7. Windows 先完成；Android 分为“应用内联动”和“跨应用系统悬浮”两个独立验收项。
8. Android 普通手指没有鼠标悬停事件；触摸期间可让视线看向触点。连接支持悬停的鼠标或触控笔时，可使用悬停跟随。

## 2. 平台可行性与实现边界

### Windows

原生分层窗口可以提供逐像素透明度，透明区域可让鼠标消息通过。项目需要同时实现：无边框置顶、透明区穿透、角色区域点击和拖动、后台获取光标位置、多显示器与 DPI 换算。不能将整个窗口设置为完全鼠标穿透后，又要求同一个窗口正常接收腹部点击。[Microsoft 分层窗口说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)

### Android 手机与平板

分两层交付，分别报告结果：

| 层级 | 目标 | 验收口径 |
|---|---|---|
| 应用内 | 奶蛙在本应用中显示、拖拽、互动，并跟随本应用软键盘 | 先实现，作为状态机、姿态、输入法动画的可控验证环境 |
| 系统悬浮 | 奶蛙可显示在其他普通应用上方，保持互动；键盘出现时自动调整位置 | 需要悬浮授权、后台生命周期和实际输入法组合验证，单列能力报告 |

`TYPE_APPLICATION_OVERLAY` 需要 `SYSTEM_ALERT_WINDOW` 授权，且有系统窗口层级约束；Android 12 起，穿过不可触摸覆盖窗口的触摸事件还有额外限制。PNG 透明不等于整个透明矩形都可以安全地穿透触摸。[Android 窗口参数文档](https://developer.android.com/reference/android/view/WindowManager.LayoutParams)

键盘打开、窗口焦点、窗口标志与输入法位置相互影响。奶蛙点击时应保持原输入框焦点和键盘可见。应用内收到的键盘信息不能直接视为“所有第三方应用的全局键盘信息”。跨应用键盘定位必须通过系统悬浮宿主实测；不可用时明确标记该组合不支持自动定位。[Android 键盘与覆盖窗口文档](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility)

本轮移动端以 Android 为范围。系统权限不足时保留应用内功能；权限被撤销时清理悬浮窗口并说明状态。仅获取键盘可见性和几何位置，不采集输入内容。

## 3. 素材清单与导入规则

规划包内 `assets/source/` 是本轮选定素材；`asset-inventory.json` 记录源路径、尺寸、哈希、透明范围及动画时序。

| 资源 ID | 源素材 | 用途 | 已知信息 |
|---|---|---|---|
| `idle` | 原始可爱蛙.png | 自由站立、眼睛跟随底图 | 320×320，RGBA，名义角色高 260 像素 |
| `sway` | 晃动一.gif | 腹部互动 | 320×320，37 帧，原动作合计 4390 毫秒 |
| `sit_1` | 坐姿一.png | 键盘上方初始姿态 | 320×320，半身抱臂姿态 |
| `sit_2` | 坐姿二.png | 键盘点击后的姿态 | 320×320，半身托腮姿态 |
| `bottom` | 底部一.png | Windows 底部趴姿 | 320×320，横向低姿态 |
| `peek_left` | 左右一.png | Windows 左边探头 | 320×320，右边由运行时镜像派生 |

### 导入时必须完成

1. 将原件作为只读素材输入，派生文件输出到 `assets/derived/`；应用发布资源使用相对路径，不依赖桌面上的个人目录。
2. 对 GIF 解码，正确处理透明色、局部帧和 disposal，保留 37 个完整可渲染画面及每帧原始时长。即使源 GIF 设置了无限循环，运行时 `sway` 仍按一次播放。
3. 同时记录透明可见范围与用于几何校准的有效轮廓范围。低透明度抗锯齿边缘不能决定坐姿接触点和点击区域。
4. 给每个姿态人工确认 `head`、`eyes`、`root`、`dragPivot`、`bottomContact`、`keyboardContact` 和侧边连接锚点；不同姿态的接触锚点可以不同。
5. 坐姿一、坐姿二当前是半身素材；本轮按半身键盘停靠资产使用，不自行添加坐凳、腿或桌子。
6. 输出瞳孔层、眼睛遮罩、腹部热区、角色触摸轮廓和过渡帧素材。
7. 渲染使用一致的颜色空间和透明混合规则，检查白底、深色底及彩色底上的边缘光晕。

### 统一尺寸的原则

使用同一角色逻辑坐标系和缩放系数，保留各姿态的合理头部、身体比例。趴姿和半身姿态的外接框高度自然不同。切换时用身体接触锚点对齐，避免腿脚突然升降、坐姿漂在键盘上方或侧边图偏出屏幕。

坐姿素材的脚下接触点实际是下沿，不能直接用 320 像素画布底边来贴键盘。镜像后，锚点、点击区域和拖动支点必须与图像一起变换。

## 4. 推荐技术架构

采用 Flutter / Dart 共享产品界面、交互状态机与二维渲染逻辑，通过原生宿主处理系统能力：Windows 使用 C++ / Win32，Android 使用 Kotlin。Flutter 官方支持通过平台通道与这些宿主交互。[Flutter 平台通道说明](https://docs.flutter.dev/platform-integration/platform-channels)

Windows 的透明合成和输入穿透先做小型验证。若 Flutter 宿主的透明表面无法满足要求，可由 Windows 原生分层窗口直接绘制同一组帧与眼睛图层，共享素材协议和状态逻辑，记录技术决策。不能在原生能力未经验证时承诺“一套界面代码覆盖所有系统差异”。

### 模块边界

| 模块 | 职责 |
|---|---|
| `pet_core` | 纯 Dart 状态、事件、规则、可取消的动画调度，不依赖窗口与网络 |
| `pet_renderer` | 帧序列、眼睛图层、镜像、缩放、遮罩与渲染 |
| `platform_host` | Windows 原生窗口或 Android 悬浮/应用内宿主 |
| `input_router` | 鼠标、触摸、腹部命中、拖拽识别、坐标转换 |
| `dock_controller` | 工作区、边缘判定、键盘停靠、位置恢复 |
| `asset_pipeline` | GIF 解码、派生眼睛层、素材检查、转场图集与清单 |
| `intelligence` | 未来接入对话、记忆和工具能力的独立接口 |

建议目录：

```text
naigui/
  apps/naigui_app/             # Flutter 应用、设置与预览
  packages/pet_core/           # 可独立测试的交互核心
  packages/pet_renderer/       # 角色渲染
  plugins/pet_host_windows/    # Windows 原生宿主
  plugins/pet_host_android/    # Android 应用内/系统悬浮宿主
  assets/source/              # 原始资源
  assets/derived/             # 图层、帧图集、过渡帧
  tools/asset_pipeline/       # 素材转换与检查
  test/                      # 单元、素材、集成测试
  docs/                      # 需求、平台能力报告、验收录像说明
```

Codex 执行时选定稳定工具链并锁定版本，记录开发环境和构建命令；不在规划阶段凭空绑定第三方悬浮插件。

## 5. 交互状态与优先级

使用分离的状态维度，避免一个巨型枚举组合所有情况：

- `layoutMode`：`free / bottom / left / right / keyboard`。
- `pose`：`idle / sway / sit_1 / sit_2 / bottom / peek`。
- `transition`：起止姿态、当前进度、取消标识。
- `dragSession`：是否拖动、指针 ID、抓取支点、待停靠位置。
- `desiredPose`：用户最新意图；异步回调不能覆盖更新的意图。

布局改变、键盘事件、点击动作由统一控制器决策。最高优先处理权限丢失、宿主销毁等生命周期事件；其后是键盘布局约束、拖动与停靠，再处理普通点击动作。

### 主要状态规则

| 当前情况 | 事件 | 目标 |
|---|---|---|
| 自由站立、静止 | 腹部点击 | 静止→晃动过渡，然后播放一次晃动 |
| 晃动进入中或播放中 | 再次腹部点击 | 从当前可见姿态平滑退出，回静止 |
| 晃动完整结束 | 播放完成 | 晃动→静止过渡，然后静止 |
| 正在退出晃动 | 又一次腹部点击 | 按最新意图重新进入晃动，废弃旧完成回调 |
| Android 软键盘出现 | 键盘几何事件 | 进入键盘停靠和坐姿一 |
| 键盘停靠、坐姿一 | 点击角色 | 坐姿一→坐姿二过渡，停留坐姿二 |
| 键盘停靠、坐姿二 | 再次点击 | 坐姿二→坐姿一过渡 |
| 键盘关闭 | 键盘几何事件 | 恢复此前布局及基础姿态 |
| Windows 拖近底边 | 边缘进入 | 过渡到底部一；松手后确认停靠 |
| Windows 拖近左边 | 边缘进入 | 过渡到左右一；松手后确认停靠 |
| Windows 拖近右边 | 边缘进入 | 过渡到左右一的镜像；松手后确认停靠 |
| 从停靠区域拖离 | 边缘离开 | 平滑恢复自由站立，继续当前拖动 |

所有动画完成回调携带播放批次 ID，旧批次完成时直接丢弃。快速连点采用最新意图收敛，避免叠加多个动画播放器、计时器和人物图层。

## 6. 眼睛跟随与点击、拖动

### 眼睛跟随

1. 静止图拆分为眼部底图、左右瞳孔/高光图层、眼睛裁剪遮罩。
2. 先移除底图上已经画好的原瞳孔，再绘制可移动层，避免出现双瞳孔。
3. 将屏幕光标转换到角色逻辑坐标，按照每只眼睛中心计算方向，在虹膜允许范围内限幅移动。
4. 初始接近半径建议 120 个逻辑像素，可配置；以角色有效轮廓为参照。
5. 初始平滑时间 80～120 毫秒；光标离远、宿主失效时回正。
6. 眼睛范围根据素材标注，初始最大偏移约 1.5～3 个角色像素，再按实际观感调整。
7. 晃动和坐姿期间先使用素材原本眼神；进入动作时，瞳孔归中与动作过渡协调，不能瞬间跳眼位。
8. Windows 光标来源使用宿主提供的全局位置，不能只监听角色窗口内部的鼠标移动。

### 命中与手势

- 腹部热区按身体轮廓标注，覆盖浅色肚皮与相邻黄色腹部，不采用“只检测黄色像素”的方式；排除头、眼睛、手和脚。
- 点击在指针抬起时确认。位移超过拖动阈值后转为拖拽，结束拖拽不能再触发腹部点击。
- 初始拖动阈值建议 Windows 4 DIP、触摸 8 DIP，写入配置。
- Windows 保持角色区域可互动，透明区穿透；不会因为画布有 320×320 就拦住整个矩形下的其他软件。
- Android 尽量收紧悬浮窗口和实际输入范围；透明区域的触摸行为必须在目标 Android 版本实测，不能仅凭 Flutter 内部命中测试宣称已实现系统穿透。
- 拖动过程中保持原抓取点跟手；姿态外接框变化不能使角色突然从手指或光标下跳开。

## 7. 动画与补帧方案

### 晃动时序

`晃动一.gif` 已核验为 37 帧、原动作 4390 毫秒，帧时长不统一。运行时按时间戳调度，保留源动作节奏，不把每一帧强制设为同样时长。

默认完整互动：

```text
静止 → 入口桥接（约180～240ms）
     → 原晃动完整一遍（4390ms）
     → 出口桥接（约180～240ms）
     → 静止
```

入口和出口时间另计，不从完整晃动动作中截走帧。全部时长均可在动作配置中调整。

### 需要新增的素材

| 转场 | 建议初始规格 | 重点 |
|---|---|---|
| 静止→晃动起始 | 180～240ms，约6～8个中间姿态 | 脚底、腹部、肩膀、手臂衔接 |
| 晃动结束→静止 | 同上 | 首尾轮廓、肤色与表情连续 |
| 晃动任意原帧→静止 | 覆盖全部37个原始帧位置的退出路径 | 第二次点击不能先跳到最后一帧 |
| 坐姿一↔坐姿二 | 200～300ms，约8～10个中间姿态 | 抱臂到托腮的手臂轨迹、嘴角与眼睑 |
| 站立↔底部姿态 | 200～350ms，按观感调整 | 身体重心和接触点 |
| 站立↔侧边探头 | 200～350ms，按观感调整 | 侧边连接点、手的位置、镜像一致性 |
| 站立↔键盘坐姿 | 按键盘出现/收起时序适配 | 坐姿下沿与键盘上缘连接 |

制作方法：先统一原帧与目标帧的角色锚点、比例及色调，再绘制/生成关键姿态、补齐中间帧；小幅位移可以使用通过验收的网格形变或光流。只凭两张端点图片，不能默认自动生成的每一帧都自然。

运行时选择可控帧序列或图集，支持当前帧读取、暂停、单次播放、中断和反向过渡。简单交叉淡化可用于开发占位，但“叠出两套手臂/重影”的结果不能通过最终连贯性验收。

中断路径可采用逐原帧预计算短退出序列，或经过验收的当前姿态形变方案。无论采用哪一种，都要覆盖动画的任意时刻，而不只处理完整播放结束。

转场中改变目标时，从当前可见结果继续过渡，不能重置为另一个转场的首帧。中间帧资源尚缺时，报告为资源缺项，不能把动作模块标记为最终完成。

## 8. 停靠与 Android 键盘几何

### Windows 边缘

- 初始进入阈值建议 24 DIP，离开阈值 48 DIP，增加约 120ms 的稳定判定，减少边缘抖动。
- 拖动过程中进入范围即给出姿态过渡预览，松手确认停靠。
- 底部按“底部一”的身体接触锚点对齐工作区底边；侧边按连接锚点对齐工作区左右边。
- 右侧执行图像水平镜像，同步镜像遮罩、热点、眼睛与连接锚点。
- 多显示器按照角色所在显示器的工作区判断；跨屏时重新计算 DPI 和坐标。
- 显示器移除或分辨率改变时，将角色恢复到可见工作区。启动时恢复位置、缩放和布局，动作从对应基础姿态开始。

### Android 键盘

平台层发布结构化事件：`visible`、键盘遮挡矩形集合、坐标空间、事件来源、可靠性、所属宿主范围。

- 只在软件键盘实际可见时进入键盘模式；仅连接物理键盘不触发。
- 键盘升降时，坐姿接触锚点跟随其上边缘，初始间距 4～8 DIP；避免遮挡按键。
- 点击奶蛙不抢走原输入框焦点，不导致键盘收起。
- 坐姿切换时，下沿接触锚点保持稳定；不能因为两张 PNG 的透明留白不同而跳高。
- 键盘模式允许有限横向拖动，仍保持坐在键盘上方的约束。
- 平板横竖屏、分屏、浮动键盘与分体键盘单独测试。无法获得可靠矩形时使用明确的兼容模式，并标注自动定位尚未满足。
- 系统悬浮需要验证权限、前台/后台生命周期和目标 SDK 约束；服务类型、通知与恢复策略按实测及官方要求实现。
- 保留应用内模式作为可用路径；跨应用联动是否完成按真机结果单列，不能用模拟按钮代替真实键盘事件。

## 9. 智能层预留

当前未定义首批智能任务，先设计以下接口及假实现用于连通性测试：

- `ConversationProvider`：可配置模型服务、流式文本、取消和超时。
- `MemoryStore`：本地保存用户明确允许记忆的偏好，可查看和删除。
- `ToolRegistry`：后续接入提醒、应用操作等已明确需求的工具。
- `PetIntentBridge`：智能结果输出有限的角色意图，交互状态机决定执行时机。

模型请求在独立异步流程运行。断网、服务超时或未配置服务时，眼睛跟随、晃动和拖拽仍可正常使用。服务凭据使用系统安全存储或服务端保管，不写入素材、安装包配置或日志。

下一轮确定“首批智能功能清单、模型来源、费用方式和工具授权范围”后，再进入智能功能实现阶段。

## 10. 素材清单协议

每个姿态至少包含：资源 ID、源尺寸、有效轮廓、渲染偏移、锚点、命中遮罩、默认缩放、可镜像标记。

每个动作至少包含：帧路径、逐帧时长、循环策略、进入/退出规则、可中断点、桥接资源、当前完成状态。

每个眼睛组件至少包含：中心、瞳孔初始位置、可移动范围、裁剪遮罩、与原姿态的绑定关系。

将“动作资源、状态规则、平台能力、智能服务”分开配置，后续增加素材不要求重写原生窗口代码。

## 12. 验收用例

### 桌面交互

- T01：启动后出现透明静止奶蛙，无边框、黑底或白色矩形。
- T02：指针在角色透明留白处可操作后方窗口，在角色腹部可正常互动。
- T03：光标从四个方向靠近，瞳孔正确跟随；移动到远处后平滑回正。
- T04：点击腹部后，完整播放37个原始动作帧，原动作时长4390ms，之后回静止。
- T05：分别在入口过渡、动作中段、最后一帧和出口过渡中再次点击，按规则平滑响应，无跳帧、重影和旧计时器抢回状态。
- T06：快速连续点击10次，最终状态由最新意图决定，只存在一个有效动作播放任务。
- T07：腹部起始拖动角色，松手后不意外触发晃动。
- T08：拖入底部切换趴姿；拖离后恢复站立，抓取点仍跟手。
- T09：左右边缘图方向正确，右边镜像后的手和停靠点正确；角落处理稳定。
- T10：Windows 100%/150%/200%缩放、正负坐标副屏、任务栏位置改变后，命中和停靠仍对齐。

### Android

- T11：同一逻辑支持手指点按和拖动，动作过程中可中断。
- T12：软件键盘升起时，以坐姿一出现在上缘；点击顺滑切坐姿二，再次点击返回。
- T13：点击宠物时原输入框仍有焦点，键盘不被意外收起，按键不被宠物透明矩形阻挡。
- T14：关闭键盘恢复原位置；快速开关键盘5次不出现旧事件残留或坐姿卡死。
- T15：手机横竖屏、平板分屏、物理键盘、至少一种系统键盘和一种第三方键盘记录实测结果。
- T16：系统悬浮权限拒绝/撤销、应用切后台与锁屏后，不遗留不可交互的遮挡窗口。

### 画面与可靠性

- T17：白、深色、彩色背景下检查全部姿态与桥接帧，无明显色跳、边缘光晕、双手重影、肢体缺失或接触点跳动。
- T18：待机期间使用事件驱动或降频更新，不持续高帧率重绘整套静止画面。
- T19：动画目标至少稳定30fps；点击后100ms内开始可见反馈，记录测试机器与测量方式。
- T20：模型服务未配置、超时或断网时，本地交互保持正常。

状态机用假时钟做自动化测试；素材做帧数/时长/锚点/透明范围检查；系统穿透、键盘焦点与跨应用位置需真实宿主集成测试。性能数据以实际 Release 构建测量，不以规划值代替测试结果。

## 13. 交给 Codex 的执行要求

1. 先阅读本方案、素材清单和当前目录约定，确认实际工具链。
2. 按 P0→P5 顺序推进，优先做 Windows 的关键系统能力验证。
3. 保持核心状态逻辑与平台代码分离；新增动作通过资源和规则扩展。
